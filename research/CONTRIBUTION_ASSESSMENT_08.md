# The field-source comparison is now constructive, not merely bibliographic

27 September 2026. Manuscript writing remains on hold. This updates the scientific
assessment without changing any previous proof, fixture, source API or license.

## What this audit settles

[The character/Taylor audit](../audits/character_taylor_v1/README.md) implements a
complete alternative to the prime-field source compiler's query method. It
rechecks the SAME untrusted serialized certificate and supports the SAME exact
all-target membership and least-period output. It retains arbitrary repeated
factors. Its compilation/query path does not call the original compiler, cyclic
solver or unipotent recognizer; basic arithmetic and prime checking remain shared.

The proof is built from standard character relations and local Taylor/Jordan
blocks. Nilpotent timing is read from a binomial row using characteristic digits,
then every coefficient is replayed. The result has the same coarse polynomial
certificate size, deterministic checking and query bounds. Neither path is forced
to enumerate an orbit or solve a target finite-field logarithm. The construction
cost of common source factor/order/alignment data is not erased.

This closes the specified comparison at the representation/guarantee level.
It is NOT a claim that a retrieved prior package implements the whole interface,
not a native performance benchmark, and not historical proof that no aspect of
the interface can be original. It shows that the main coarse algorithmic promise
follows constructively from a conventional algebraic route at comparable bounds.

## The missing direct paper is no longer an access bottleneck

A readable PDF was found by following the author's publication list, not by
retrying the unusable publisher scan. Its complete mathematical text, especially
the Jordan-block order formula and reduction, has now been inspected. The
[source dossier](../audits/character_taylor_v1/SOURCES.md) records the primary
copy, exact scope, a small index-conversion caveat, and the bibliography date
discrepancy. The old audit files are preserved as historical reading records.

## Current decision

Treat the existing algebraic source compiler as a certifying implementation and
reformulation of established structure. Do not present its polynomial-size,
no-target-logarithm query guarantee alone as a cleared novel algorithmic theorem.
The primary-power reduction remains a supporting corollary under this assessment.
The prior query-hardness work remains a scope result with its own predecessors.

The mathematical core and test infrastructure are not discarded. They provide a
well-specified exact engine and two independently organized recognition paths.
However, the scientific work needed for an original paper is not complete.
A custom format, repeated-factors extension, long orbit or extra test suite does
not close that gap. Another equivalent algebraic format is not the next task.

## A concrete next gate instead of more domain expansion

The project should now earn a verification contribution. Before implementing
anything further, identify a meaningful obligation that an existing verifier
cannot discharge at the same cost or assurance level, using the same arithmetic
and equally compact representations. Specify the consumer, strongest comparator,
and success/failure criterion. Then choose one of: a strictly justified checker
cost/assurance result, or an executed useful proof-producing integration. Neither
is predeclared achievable or already established by this audit.

The old strongest theorem can be a baseline inside that investigation. It should
not remain the assumed novelty around which more auxiliary results accumulate.
Formalization is not automatically the answer either: it is a contribution only
when the assurance goal, trusted boundary and prior verified alternatives make
its value explicit. No target venue is recorded and no manuscript drafting is
started. Repository merge/CI status belongs to Git history and receipts, not to
claims of mathematical priority.
